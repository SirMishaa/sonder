# YouTube player: real playback + listening history

## Problem

Sonder's player UI (`PlayerBar`, `QueuePanel`, shortcuts, `playTracks` /
`playNext` wired into the pages) runs on a front-end fixture:
`resources/js/composables/usePlayer.ts` fakes playback with a timer. Nothing
plays. We also have no record of what the user listens to, which the future
suggestion algorithm needs.

YouTube Music exposes no playback-control API: `ytmusicapi` only covers
library data, and the web client's `/api/stats/watchtime` calls are one-way
telemetry beacons. A throwaway test page (`public/player-test.html`) validated
the YouTube IFrame Player API instead: `controls=0`, driven entirely from our
own UI, keeps playing in a background tab and when the player is hidden 1px
offscreen, and shows no ads because the user's YouTube Premium session is
recognised through the `youtube.com/embed` cookies.

## Goals

- Real playback of synced tracks through the YouTube IFrame API, driven by the
  existing Sonder controls (play/pause, previous/next, seek, volume, queue).
- Record one row per listen, including when and why the user moved on, as
  input for suggestions.
- Keep the test page's debug view as an in-app panel behind a discreet link.
- Test the front end: pure logic in node, components mounted in a real
  browser.

## Non-goals

- Controlling a YouTube Music tab or the YTM app (would need a browser
  extension; rejected as more work and desktop-only).
- Multi-device control or remote "now playing" (would need Reverb commands;
  separate brick).
- Mobile background playback and lock-screen controls (the browser stops
  embedded playback when backgrounded on iOS/Android; accepted limitation).
- Retrying failed listen submissions.
- The suggestion algorithm itself.

## Known constraints and accepted risks

- **YouTube API Terms of Service** forbid a hidden player (minimum ~200×200).
  Accepted for a personal project; revisit if Sonder opens to other users.
- **`display: none` / `visibility: hidden` break the player** (it may never
  fire `onReady`), hence 1px offscreen with `opacity: 0`.
- **Ads come back** if the browser blocks third-party cookies for
  youtube.com. The user's browser was verified to work.
- **Some tracks refuse embedding** (errors 101/150): skipped automatically.
- **Autoplay** can be blocked when the tab has had no user interaction (for
  example after a reload): restore paused, a click resumes.

## Design

### Data model

Table `listens`, model `Listen`: one row per listen.

| Column | Type | Notes |
|---|---|---|
| `id` | uuid, primary | Generated by the client (idempotency) |
| `user_id` | FK users, `cascadeOnDelete` | |
| `youtube_video_id` | string, index | Stable track identity |
| `title`, `artists` | string | Snapshot at listen time |
| `youtube_playlist_id` | string, nullable | Source playlist |
| `origin` | string, enum `ListenOrigin` | How the listen started |
| `end_reason` | string, enum `ListenEndReason` | How it was left |
| `started_at`, `ended_at` | timestamp | |
| `position_seconds` | unsigned int | Position when the listen ended ("switch timing") |
| `listened_seconds` | unsigned int | Time actually played, excluding pauses and seeks |
| `duration_seconds` | unsigned int, nullable | Track duration reported by the player |

Index `(user_id, started_at)`.

`ListenOrigin` (how *this* listen started): `Playlist` (a playlist started
at a track), `Search`, `Suggestion`, `Queue` (the user moved within the queue:
click, next or previous button), `Autoplay` (automatic advance at the end of a
track).

`ListenEndReason`: `Ended` (played to the end), `Skipped` (next button),
`Previous` (previous button), `Jumped` (click in the queue), `Replaced` (a new
playlist was started), `Picked` (another track started from outside the queue:
search, suggestion), `Error` (player error), `Abandoned` (page closed).

No foreign keys to `tracks` or `playlists`: the sync deletes and recreates
tracks (`SyncPlaylistTracks`), which would orphan or cascade-delete history.
YouTube ids are stable across syncs; `title`/`artists` are copied so history
stays readable and suggestion queries need no join. Very short listens,
including 0s errors, are kept: a skip after 2s is a strong signal.

### Backend

- Route `POST /listens`, in the `auth` + `verified` group, named
  `listen.store`, `throttle:120,1`.
- `ListenController@store`: thin, delegates to the action, returns `204`.
- `CreateListenRequest` validation:
  - `id`: required uuid.
  - `youtube_video_id`: required, max 11, `[A-Za-z0-9_-]`.
  - `title`, `artists`: required, max 255.
  - `youtube_playlist_id`: nullable, max 64.
  - `origin`, `end_reason`: `Rule::enum()`.
  - `started_at`, `ended_at`: ISO dates, `started_at <= ended_at <= now + 1 minute`
    (clock skew).
  - `position_seconds`, `listened_seconds`: integers 0–86400;
    `duration_seconds`: nullable, same bounds.
  - After validation: `listened_seconds <= (ended_at - started_at) + 5`.
- Action `RecordListen::handle(User $user, array $attributes)`:
  `insertOrIgnore` keyed on the client `id`, so a duplicate submission is a
  no-op. `user_id` always comes from the authenticated user, never the body.
- Telemetry: an OpenTelemetry counter `sonder.listens` incremented in
  `RecordListen`, with `end_reason` and `origin` attributes.

### Frontend

**`resources/js/lib/player/`** (framework-free logic):

- `transport.ts`: `PlayerTransport` interface.
  - Commands: `load(videoId, { startAt, autoplay })`, `play()`, `pause()`,
    `seek(seconds)`, `setVolume(volume)`, `setMuted(muted)`, `currentTime()`,
    `duration()`, `videoId()`.
  - Events: `ready`, `state` (`playing` / `paused` / `buffering` / `ended` /
    `cued`), `error(code)`, `autoplayBlocked`.
- `youtubeTransport.ts`: implementation over `YT.Player`; loads
  `https://www.youtube.com/iframe_api` once; `host: https://www.youtube.com`
  (never `youtube-nocookie.com`), `controls: 0`, `disablekb: 1`,
  `playsinline: 1`, `rel: 0`, `iv_load_policy: 3`, `origin`.
- `fakeTransport.ts`: in-memory, test-drivable implementation.
- `listenTracker.ts`: the current listen. Creates the `id`
  (`crypto.randomUUID()`), accumulates `listened_seconds` from time deltas
  while playing (a jump over 2s counts as a seek, not listening), and builds
  the payload on `end(reason)`.
- `listenSender.ts`: `send(payload)` through Inertia's `useHttp` (XSRF header
  handled by Inertia); `sendOnUnload(payload)` through
  `fetch(url, { method: 'POST', keepalive: true })` with the `X-XSRF-TOKEN`
  header read from the `XSRF-TOKEN` cookie, because the XHR client cannot
  outlive `pagehide`. The URL comes from Wayfinder
  (`ListenController.store()`).

**`usePlayer.ts`** keeps its public API; the fake timer goes away.

- `attachTransport(transport)`, called by the host. Every command (`toggle`,
  `jumpTo`, `next`, `previous`, volume, mute, seek) goes through it.
- `elapsed` and duration come from the player, polled every 250ms only while
  playing.
- `ended` → `next()` with origin `Autoplay`.
- "Previous" after 3s of playback seeks back to 0 on the same track: the
  listen continues (treated like a seek), no new row.
- Errors 100/101/150 → skip to the next track, toast, debug-log entry.
- Reload → restore the track and position with a cue (paused), since
  autoplay without a gesture is blocked.
- `playTracks` / `playNext` take an origin: `playlist/Show` → `Playlist`,
  `CommandPalette` → `Search`, `discover` → `Suggestion`; a click in the queue
  → `Queue`.
- Every track change ends the current listen with the matching reason and
  sends it; `pagehide` ends it as `Abandoned` through `sendOnUnload`.
- Debug log: ring buffer of the last 200 events (state changes, loads,
  errors, send results).

**Components:**

- `shell/PlayerHost.vue`, mounted once in `AppLayout` (persistent layout, so
  it survives navigation): a 1px offscreen element with `opacity: 0`,
  `pointer-events: none`, `aria-hidden="true"`, `tabindex="-1"`. Creates the
  YouTube transport in `onMounted` (SSR-safe).
- `shell/PlayerDebugPanel.vue`: player state, expected vs actual `video_id`,
  player vs stored duration, "likely ad" badge (heuristic: other `video_id` or
  duration off by more than 5s), errors, event log. Opened from a `text-faint`
  "debug" link at the bottom of `QueuePanel`.
- `PlayerBar` and `QueuePanel` stay essentially unchanged; they already read
  `usePlayer`.

`public/player-test.html` is deleted once the debug panel exists.

### Error handling

- `iframe_api` fails to load (blocker, network): toast "Player unavailable",
  controls disabled, debug entry.
- `autoplayBlocked`: state goes to paused; play stays available so a click
  resumes.
- Listen submission fails (network, 5xx): console + debug entry, no retry.
- `422` on submission: debug entry with the validation errors (signals a
  payload bug).

### Testing

**Front end**, through `vp test` (Vite+ bundles Vitest 5 with browser mode
and the Playwright provider); a `test` script in `package.json` and two
Vitest projects in `vite.config.ts`:

- `unit` (node):
  - `listenTracker`: accumulation, pause adds nothing, seeks are not counted,
    payload on `end(reason)`.
  - `usePlayer` over `fakeTransport`: `playTracks` loads the right track;
    `ended` → next with `Autoplay` and the listen ends `Ended`; skip →
    `Skipped` and the next listen starts `Queue`; previous within 3s →
`Previous`, after 3s → same listen continues from 0; queue click →
    `Jumped` + `Queue`; search `playNext` → `Picked` + `Search`; error 150 →
    skip and `Error`; restore on reload cues paused; `pagehide` →
    `sendOnUnload` with `Abandoned`.
- `browser` (Chromium via Playwright), components mounted with
  `vitest-browser-vue` and an injected `fakeTransport`:
  - `PlayerBar`: play/pause calls the transport and the label follows the
    state; seek; volume.
  - `PlayerDebugPanel`: shows state, the "likely ad" badge when `video_id`
    differs, errors.
  - `PlayerHost`: element is offscreen, 1px, `aria-hidden`; does not crash
    without `window.YT`.
- No real YouTube calls in tests (slow, flaky). The real
  `youtubeTransport` was validated by hand with the test page and gets a
  final manual browser check.

**Back end** (Pest): valid listen → `204` and row created; same `id` twice →
one row; guest → redirect; invalid fields including an inconsistent
`listened_seconds` → `422`; `user_id` in the body is ignored.
